# Каналы задач: мессенджеры, почта, трекеры, Siri и уведомления

Задачу агенту можно поставить сообщением из мессенджера или письмом. Nexus превращает его в обычный чат проекта, присылает ход выполнения, запросы разрешений и итог обратно в тот же разговор.

Настройка: **Подключения → Каналы**.

## Как это работает

1. Канал опрашивается в фоне, пока Nexus открыт на Mac (`remote_channels::start_bridge` из `setup`).
2. Сообщение от отправителя **из списка разрешённых** становится задачей: создаётся чат «Telegram · …» в выбранном проекте (или продолжается текущий чат разговора) и вызывается тот же `unified_chat_send`, что и из интерфейса. Задача видна в «Цели и задачи» и в дереве чатов.
3. События `chat-progress`, `chat-permission`, `chat-question` для удалённых запусков пересылаются в канал. Итог ответа отправляется с маршрутом, режимом и статусом задачи (`project_board`).

## Команды

| Команда | Действие |
|---|---|
| текст | новая задача (в текущем чате разговора) |
| `/status` | текущий этап, ожидающие разрешения, последние задачи проекта |
| `/stop`, `/continue` | остановить; дописать остановленный ответ |
| `/projects`, `/project 2` | список и выбор проекта (по номеру или имени) |
| `/agent`, `/agent auto`, `/agent codex/gpt-…` | список агентов, автовыбор, ручной выбор (без молчаливой замены) |
| `/mode discuss`, `/mode execute` | режим «Обсуждение» / «Выполнение» |
| `/allow КОД`, `/deny КОД` (или «да»/«нет», если ждёт ровно один запрос) | однократный ответ на запрос разрешения агента |
| `/new` | следующая задача в новом чате |
| `/help` | справка |

Русские синонимы: `/статус`, `/стоп`, `/продолжить`, `/проект`, `/агент`, `/режим`, `/новый`, `/разрешить`, `/отклонить`. Суффикс Telegram `/status@Bot` поддерживается.

## Безопасность

- Список разрешённых отправителей обязателен для включения. Остальные сообщения игнорируются; Telegram/Discord/Slack один раз отвечают неизвестному ID (чтобы владелец мог его добавить), iMessage и Email — молча.
- По умолчанию «Обсуждение». «Выполнение» доступно, только если в настройках канала включено «Разрешить режим „Выполнение“».
- Удалённое `/allow` всегда однократное (`remember=false`): постоянные разрешения проекта из канала не создаются. Кто ответит первым — в Nexus или в канале — тот и решает.
- Код запроса — 6 случайных символов из системного генератора (`random_code`), а не производная от номера запроса. Ответ без кода («да»/«нет») принимается только в Telegram, Discord, Slack, iMessage и локальном API, где отправителя нельзя подделать; в почте, GitHub и Linear нужен `/allow КОД`.
- Токены и пароли хранятся в связке ключей macOS (`com.nexus.connections`, аккаунт `channel-<kind>`), передаются curl только через stdin-конфиг, не попадают в argv, JSON и журнал.
- При включении канала (и смене канала/ящика) курсор сбрасывается: старые сообщения пропускаются, задачами становятся только новые.
- Email: принимаются только письма, у которых верхний `Authentication-Results` содержит `dmarc=pass` или `dkim=pass` с доменом подписи (`header.d`), совпадающим с доменом отправителя (`mail_authenticated`). Просто `dkim=pass` недостаточно: любой домен может подписать письмо с чужим адресом в From. Флаг «без DKIM/DMARC» — только для собственного сервера. Ответы помечены `X-Nexus-Reply` и `Auto-Submitted`, чтобы не зациклиться.
- В сообщение о разрешении попадает до 600 символов команды/пути — они уходят в ваш собственный канал.

## Каналы

| Канал | Получение | Ответ | Что нужно |
|---|---|---|---|
| Telegram | Bot API `getUpdates` (long polling 25 с) | `sendMessage`, части ≤3900 | токен @BotFather, ID пользователя (бот присылает его на `/start`) |
| Discord | REST `GET /channels/{id}/messages?after=` раз в 3 с | ответ-ссылка на сообщение, части ≤1900, без упоминаний | токен бота, **Message Content Intent**, ID канала, ID пользователей |
| Slack | `conversations.history` раз в 4 с | `chat.postMessage` в ветку | `xoxb-` токен, scopes `channels:history`/`groups:history`, `chat:write`, бот приглашён в канал |
| Email | IMAP `UID SEARCH`/`FETCH` раз в 30 с | SMTP, ответ в ту же цепочку | IMAP включён, пароль приложения; TLS обязателен (993/465 или STARTTLS) |
| iMessage | чтение `~/Library/Messages/chat.db` (`sqlite3 -readonly`) раз в 3 с | AppleScript «Сообщения», префикс `Nexus · ` | Полный доступ к диску и Автоматизация → Сообщения для NEXUS; только диалоги 1:1 |
| GitHub Issues | `GET /repos/{r}/issues?labels=` и `/issues/comments?since=` раз в 20 с | комментарий в issue с маркером `<!-- nexus -->` | fine-grained токен: Issues read/write; метка (по умолчанию `nexus`) |
| Linear | GraphQL `issues`/`comments` по метке и времени раз в 20 с | `commentCreate` с префиксом `Nexus · ` | персональный API-ключ; разрешённые — email авторов |
| Siri / «Команды» | локальный HTTP API (`api_server.rs`) | ответ в теле запроса и буфер `/v1/messages` | токен генерирует Nexus |

Discord без Gateway: используется опрос REST, поэтому нужен ID конкретного канала; личные сообщения боту пока не поддерживаются. iMessage «Чат с собой» принимает ваши собственные сообщения на номер из списка; ответы Nexus распознаются по префиксу, дубли в течение 90 с отбрасываются.

## Трекеры: GitHub Issues и Linear

- Задача — новое **открытое issue с меткой**, созданное после включения канала (`IssueCursor.since`). Каждое issue обрабатывается один раз (`Store.seen`), у каждого свой чат Nexus.
- Комментарии разрешённых авторов в этом issue работают как сообщения в мессенджере: уточнения задачи и команды `/status`, `/stop`, `/allow КОД`. Комментарии в issue, которые Nexus не начинал, игнорируются (`follow_up`).
- Свои ответы Nexus распознаёт по маркеру (`<!-- nexus -->` в GitHub, префикс `Nexus · ` в Linear), поэтому можно использовать собственный токен.
- В публичном репозитории ответы агента видны всем — не включайте там «Выполнение» и не ставьте задачи с секретами.

## Siri и «Команды»: локальный HTTP API

- Выключен по умолчанию. Слушает `127.0.0.1:4719`; флаг «Доступ из локальной сети» открывает `0.0.0.0` (HTTP без TLS — только в доверенной сети). При доступе из сети задачи всегда идут в режиме «Обсуждение»: токен в открытом HTTP можно перехватить.
- Не больше 16 одновременных соединений; запрос должен прийти целиком за 15 секунд (иначе 408). Разбор `%XX` в адресе не падает на не-ASCII символах.
- Каждый запрос, кроме `GET /health`, требует `Authorization: Bearer <токен>`. Токен (48 hex) создаёт Nexus и хранит в Keychain; кнопка «Новый токен» отзывает старый. Запросы с заголовком `Origin` (из браузера) отклоняются; 10 неверных токенов за 10 минут с одного IP → 429.
- `POST /v1/message` — JSON `{"text": "...", "wait": 0–55, "conversation": "siri"}` или простой текст. Текст обрабатывается так же, как сообщение в мессенджере (задача или команда). Ответ: `{"text", "messages", "running", "cursor"}`; `?format=text` — простой текст для «Произнести».
- `GET /v1/messages?after=<cursor>&conversation=` — новые ответы; `GET /v1/status` — то же, что `/status`.
- Рецепт в «Командах»: «Продиктовать текст» → «Получить содержимое URL» (POST, JSON, заголовок Authorization) → «Получить значение по ключу text» → «Произнести текст». С iPhone нужен флаг локальной сети и адрес `http://<имя-mac>.local:4719`.

## Уведомления

- ntfy (`https://ntfy.sh` или свой сервер по HTTPS): тему вида `nexus-<24 hex>` создаёт Nexus, она хранится в Keychain и передаётся curl через stdin. Тема — секрет: кто её знает, видит уведомления.
- События: задача завершена (готово / нужна проверка / ошибка / остановлена + первые 300 символов ответа) и агент ждёт разрешения (высокий приоритет). Охват: только задачи из каналов или все задачи Nexus.
- Уведомления macOS (`osascript display notification`, значения передаются через argv) — только когда окно скрыто или свёрнуто.

## Работа в фоне

- «Работать при закрытом окне» (по умолчанию включено) действует, когда включён хотя бы один источник задач: закрытие окна скрывает его (`background::on_window_event`), клик по значку в Dock возвращает (`RunEvent::Reopen`), ⌘Q завершает Nexus.
- Пока каналы активны, Nexus отказывается от App Nap (`NSProcessInfo beginActivity`, сон системы разрешён), чтобы опрос не замедлялся.
- «Запускать при входе» использует `SMAppService.mainAppService` (macOS 13+). Для сборки с ad-hoc подписью macOS может потребовать подтверждения в «Объектах входа»; статус показывается в панели.

## Файлы

- `src-tauri/src/remote_channels.rs` — конфиг (`channels.json`), курсоры и разговоры (`channel-state.json`), команды, запуск задач, пересылка событий, Tauri-команды `channels_list/save/test/remove/log`.
- `src-tauri/src/channel_adapters.rs` — адаптеры (включая GitHub и Linear), разбор писем (MIME, QP, base64, RFC 2047), typedstream `attributedBody`, разбиение длинных ответов.
- `src-tauri/src/api_server.rs` — HTTP API; `push_notify.rs` — ntfy и уведомления macOS; `background.rs` + `background_macos.m` — фон, App Nap, автозапуск.
- `src/channels-panel.jsx`, `src/channels-panel.css`, `src/channels-format.js` — вкладка «Каналы».
- Тесты: `cargo test … --lib` (модули `channel_adapters`, `remote_channels`, `api_server`, `push_notify`, `background`), `tests/channels-format.mjs`.

## Ограничения

- Работает, пока процесс Nexus запущен и Mac не спит: окно можно закрыть, но ⌘Q останавливает каналы. Отдельного демона без приложения нет.
- Код только для macOS (`Reopen`, App Nap, `SMAppService`, Objective-C) не компилировался в среде разработки — проверяется сборкой `tauri:build` на Mac.
- Вложения и картинки из каналов не принимаются — только текст.
- Вопросы агента (`chat-question`) пересылаются как уведомление; ответить на них можно только в приложении.
- Прогресс приходит не чаще раза в 20 с и не более 12 сообщений на задачу; для Email по умолчанию выключен.
- Реальная отправка через каждый сервис проверяется кнопкой «Проверить подключение» и пробным сообщением; автоматические тесты используют фикстуры ответов API.
