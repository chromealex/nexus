Срез проверен 11 ноября 2026. Это опубликованные сторонние измерения, не собственные прогоны Nexus. Покрытие всех 32 записей каталога ниже; отсутствие результата не означает плохое качество. Живой каталог может содержать дополнительные неизвестные версии.

## Методика и ограничения

- AA Intelligence Index v5.0.1 — смешанный набор из 9 оценок. Используется как косвенный ориентир для сложных задач и общего кода, а не отдельный балл исправления ошибок. Скорость выдачи и первый ответ измерены AA; минуты на задачу — расчёт времени инференса, без полного времени выполнения инструментов. API-расход учитывает токены теста и его веса, не стоимость нашей подписки.
- Arena WebDev — предпочтения в веб-разработке, не pass rate. Применяется только при распознавании frontend/React/HTML/CSS/сайта.
- Arena Text Overall — общие предпочтения текстовых ответов, не отдельная оценка перевода или русского языка.
- Arena Vision — понимание изображений, не их генерация. Показанные ± — опубликованные интервалы неопределённости; пересечение не доказывает превосходство.
- Разные режимы указаны у каждой строки. При Авто результаты служат предварительным ориентиром, режимы Max/xHigh не включаются автоматически. Для ручной глубины допускаются только совпадающие low/medium/high; ручная модель всегда сохраняется.
- Точные ID: алиасы Claude, runtime default, preview вместо stable не наследуют результаты. AA Default Fallback исключён из маршрутизации.
- Сначала фильтруются возможности и доступность, затем сравниваются минимум две точные версии внутри одного теста и даты. Незамеренные варианты не получают ноль. Покрытие показано в объяснении.
- Для AA допускается отставание до 3 баллов от лучшего: для полностью API-кандидатов выбирается меньший расход теста, затем расчётное время. Для подписок расход не используется, выбирается время. Порог 3 — продуктовая эвристика, не погрешность теста.
- Для Arena при пересечении интервалов API-кандидатов сравнивается тариф за фиксированные 10 тыс. входных + 2 тыс. выходных токенов; это условный объём, не измеренная цена задачи. Иначе используется опубликованный балл и стабильный ID.
- При недостатке данных или возрасте 90 дней — явно отмеченный резервный выбор. Снимок не обновляется сам; для обновления нужны повторная проверка источников и сборка.
- Надёжность инструментов, извлечение данных и стоимость по каждой отдельной категории пока не измерены. Отдельные точные рейтинги для этих пунктов не выдумываются.

## Источники методик

- [AA Intelligence Index v5.0.1](https://artificialanalysis.ai/methodology/intelligence-benchmarking), срез 2026-11-11. Смешанный набор сложных задач, включая код; не отдельная оценка архитектуры или исправления ошибок.
- [Arena WebDev](https://arena.ai/leaderboard/code/webdev), срез 2026-11-10. Предпочтения в веб-разработке; не доля пройденных тестов и не оценка любого кода.
- [Arena Text Overall](https://arena.ai/leaderboard/chat/text), срез 2026-11-09. Общие предпочтения пользователей; не отдельный тест перевода, русского языка или фактологии.
- [Arena Vision Overall](https://arena.ai/leaderboard/chat/vision), срез 2026-11-08. Понимание изображений, не генерация изображений.

## Обновление политики: четыре приоритета

Текущая реализация заменяет описанный выше выбор максимального балла при пересечении интервалов. В таком случае преимущество качества не считается доказанным: используются известные сопоставимые цена/время, затем стабильный ID. «Баланс» сохраняет допуск 3 балла AA; «Качество» — 0 баллов AA. Для Arena оба учитывают интервалы. «Экономия» и «Скорость» допускают снижение качества и выбирают минимум метрики среди оценённых вариантов только при её полном покрытии; иначе показывается причина резервного выбора. Неизвестные стоимость подписки и время отдельных категорий не становятся нулями. Приоритет сохраняется для каждого чата.

## Обновление 14 ноября 2026: заполненная таблица и исправленный автовыбор

Источники проверены 14.11.2026. Это по-прежнему внешние измерения, а не прогоны Nexus; платные модельные прогоны не проводились.

### Что было не так

- Claude Code в Nexus показывает алиасы `haiku` / `sonnet` / `opus`. Они не связывались с точными версиями, поэтому у Claude в таблице было «Сравнительных данных нет», а в автовыборе Claude не участвовал вообще.
- Результаты AA с пометкой «Default Fallback» исключались. Но это стандартное поведение Anthropic API и Claude Code: при отказе модели запрос переходит к резервной модели. Исключение убирало из сравнения все результаты Opus и Sonnet.
- Для кода использовалась Arena WebDev (только веб, предпочтения) или общий Intelligence Index, хотя есть индекс, который измеряет модель вместе с тем же агентом.
- У ручной глубины почти не было строк low/medium/high, и выбор всегда уходил в резервный вариант.
- Извлечение данных, надёжность инструментов и скорость Claude не имели источников.

### Что изменено

- **Алиасы.** Бэкенд (`chat_models.rs`) сопоставляет `haiku → claude-haiku-5-5`, `sonnet → claude-sonnet-5-5`, `opus → claude-opus-5-5` по [официальной таблице алиасов Claude Code](https://code.claude.com/docs/en/model-config) для Anthropic API. Если найдены `ANTHROPIC_DEFAULT_*_MODEL`, `ANTHROPIC_MODEL`, `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_USE_BEDROCK/VERTEX/FOUNDRY/ANTHROPIC_AWS` в окружении или в `settings.json` аккаунта, версия считается неизвестной и сравнения не применяются. Значения настроек не читаются в интерфейс, только имя переменной. Фактические версии из `modelUsage` ответа Claude Code пишутся в диагностику.
- **Резервная модель Anthropic** больше не исключает результат; в тексте строки стоит пометка «с резервной моделью Anthropic по умолчанию».
- **Код** → [AA Coding Agent Index v2.1](https://artificialanalysis.ai/agents/coding-agents) (FrontierCode-AA 2.0, Terminal-Bench 4.1, SWE-Atlas-QnA-AA). Строка применяется только к тому же агенту: результат «в Claude Code» — к подключению Claude, «в Codex» — к Codex. Для API-подключений используется Arena WebDev (для веба) или Intelligence Index.
- **Извлечение данных** → GDP.pdf (прогон AA): ответы по сложным PDF. Применяется, когда приложены файлы и в запросе есть извлечение (новый тип задачи «Извлечение данных»).
- **Надёжность инструментов** → AutomationBench-AA: сценарии через API приложений. Применяется, когда задаче не про код нужны инструменты (режим «Выполнение», файлы или проект).
- **Скорость** → время задачи, первый ответ и ток/с из AA; показывается режим medium (по умолчанию в Claude Code), если он опубликован.
- **Ручная глубина** теперь находит строки low/medium/high для Opus 5.5, Fable 5.2, GPT-6.1 Sol, GPT-6 Astra и сравнивает только одинаковый режим.
- **Короткие простые вопросы** (меньше 160 символов, без файлов, кода, перевода и редактуры) не сравниваются по рейтингам при приоритетах «Баланс», «Экономия», «Скорость»: иначе на «Привет» выбирался самый сильный по Arena Text флагман. Приоритет «Качество» сравнение сохраняет.
- Для процентных тестов допуск «Баланса» — 3 п.п., для индексов — 3 балла; это правило продукта, а не погрешность.

### Как теперь выбирается модель в «Авто»

1. Отбираются совместимые модели (протокол, файлы, изображения, инструменты, глубина).
2. По типу задачи берётся первый тест из цепочки, где есть минимум две точные версии:
   - код: Coding Agent Index (тот же агент) → Arena WebDev (если веб) → Intelligence Index;
   - рассуждения: Intelligence Index;
   - изображения: Arena Vision;
   - тексты: GDP.pdf (если извлечение из файлов) → AutomationBench-AA (если нужны инструменты) → Arena Text.
3. В «Авто» у каждой модели берётся лучший опубликованный режим; при ручной глубине — только тот же режим.
4. Группа близких: в пределах допуска (или пересечение интервалов Arena). Если лидер один — выбирается он. Иначе сравнивается API-расход (только для API-подключений), затем время задачи в тесте, затем стабильный ID.
5. Если данных нет — прежний резервный выбор по совместимости с объяснением.

Примеры при подключённых Claude Code и Codex: исправление кода → Opus (58 в Claude Code против 56 у Sonnet; Codex Sol 52); только Codex → GPT-6.1 Sol (52, на 1 балл ниже Astra, но быстрее: 21.9 против 26.0 мин); извлечение из PDF → GPT-6.1 Sol (32.0% против 28.8% у Opus).
